Artifact 5: Firebase Account Security + Firestore Rules (Text-Only)

For FieldFlow, I treated authentication and authorization as separate layers: users must be authenticated, and access is still restricted by server-side database rules. This reduces the risk of a client-side bypass and keeps enforcement at the policy layer.

  • Account protection through Firebase Authentication (sign-in required for private content)
  • Data isolation: rules scope reads/writes so users can only access the data they are allowed to access
  • Write protection: prevents unauthorized edits and unsafe updates by enforcing rule constraints
  • Validation workflow: attempt restricted actions → confirm permission-denied → confirm intended actions succeed

Simplified, non-sensitive rules excerpt (structure only): 

// Firestore Rules (simplified structure example)
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() { return request.auth != null; }

    // Example: each user can only access their own profile doc
    match /users/{uid} {
      allow read, write: if signedIn() && request.auth.uid == uid;
    }

    // Example: user-scoped notes (ownership checks are stricter in live rules)
    match /notes/{noteId} {
      allow read, write: if signedIn();
    }
  }
}

Live rules are more restrictive than this excerpt (ownership/membership checks + write constraints), but this shows the security approach.
